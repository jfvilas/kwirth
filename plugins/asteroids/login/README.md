# Asteroids login

A login page with the game's look: a vector asteroid field and the title drawn in strokes, with the
access panel on top.

It is the optional login extension of the **Asteroids** channel plugin for
[Kwirth](https://kwirthmagnify.dev) ([source](https://github.com/kwirthmagnify/kwirth)). It is
published on npmjs as `@jfvilas/kwirth-login-asteroids` and listed in the jfvilas marketplace
(`https://raw.githubusercontent.com/jfvilas/kwirth/master/manifest.json`): add that URL as a
marketplace in Kwirth if it is not there yet, and install it from the **login manager**.

Source: https://github.com/jfvilas/kwirth (folder `plugins/asteroids/login`).

```
npm run background   # regenerates background.png
npm run build        # packages dist/kwirth-login-asteroids.tgz
npm run watch        # rebuilds when login.json, package.json or background.png change
```

The plugin's watch (`node watch.mjs` in `plugins/asteroids/`) already launches this one, so there
is normally no need to start it separately.

## What can be changed

A login extension is the most limited artifact in Kwirth. The bundle accepts **only**
`package.json` + `login.json` + **one** `background.png`, and it is rendered by a fixed core
component: the full-page background and **a single positionable panel** with `standard` MUI fields.

There is no way to add a logo, checkboxes, links, selects or a second column. All the branding is
**baked into `background.png`** — and that branding **is not clickable**.

| `login.json` key | What it does here |
|---|---|
| `startChannel` | `asteroids`. **It is not decorative**: the core blocks the login if the user is not an admin and does not have that channel enabled. |
| `top` / `left` / `width` | Place the panel over the gap the background leaves free in the centre. |
| `textColor` | White, because the background is black. |
| `okButton` | `Insert coin`. |

## The background is generated by code

`make-background.mjs` draws the PNG (1408×768, grayscale) and writes it by hand with `zlib`, with no
dependencies. The reason is not a whim:

**`background.png` has a hard cap of 600 KB**, because it travels in base64 inside a ConfigMap.
Going over it **does not break the installation**: the login is installed **half-way, without a
background**, and you do not find out until you open the page.

Being white line art on black, this background takes **9 KB**. The problem disappears at the root
instead of being managed by recompressing. `build.mjs` checks the cap anyway and aborts if it is
exceeded.

The drawing is reproducible: the randomness uses a fixed seed, so regenerating gives the same
background. To change the composition, edit the `CLEAR` and `TITLE_BAND` zones (the gaps reserved
for the panel and the title) and the list of rocks.

## Known pitfalls

- **The background is cached for one hour in the browser.** The core sends
  `Cache-Control: max-age=3600`, in dev too. You change the background, rebuild, restart the back
  and still see the old one: the copy is in the browser. **Ctrl+Shift+R.**
- **A login from `kwirth-dev.json` is installed only when the back starts.** Rebuilding the `.tgz`
  does not refresh the served configuration: the back has to be restarted.
- **Themes do not reach the login.** The front loads them after authentication, so the form always
  uses the default MUI look: blue focus and uppercase buttons, not configurable.
- **Publish from this folder, never from `dist/`.** From `dist/`, npm puts the `.tgz` inside the
  package and the background ends up duplicated. Check with `npm pack --dry-run`.
- **`allowedIdps: []` hides every IdP** (an empty array is *truthy*). To offer them all, **omit**
  the key.
